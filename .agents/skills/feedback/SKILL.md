# Feedback

Allocate `FB-NNNN` and use the Feedback template. Record source, severity,
related Feature/Work Order/Test, observed behavior, expected behavior for bugs,
reproduction/evidence, and uncertainty. Classify before action:

- `BUG`: implementation violates approved spec → fix/new Work Order.
- `SPEC_DEFECT`: Requirement/Feature/Blueprint wrong or ambiguous → owning role
  and lifecycle rollback.
- `IMPROVEMENT`: correct behavior with a better opportunity → backlog/revision.
- `DISCOVERY`: fundamentally new product/technical/market/player truth → Producer
  and Directors/Executive Producer when material.

Do not relabel a spec defect as a bug to avoid revising artifacts. Record routing,
resolution, linked successor IDs, and closure evidence.

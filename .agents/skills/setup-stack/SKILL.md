# Stack Setup

Inspect manifests, lockfiles, CI, source roots, existing architecture, platforms,
and constraints before asking. Configure separately: Runtime, Primary Language,
Secondary Languages, Client/Rendering, Simulation Runtime, Server/Backend,
Persistence/Database, Build System, Package Manager, Testing, Target Platforms,
and Deployment. Support web/TypeScript/Phaser/PixiJS, Python, Rust/web, C++ custom,
headless, engine/external-service, and mixed stacks.

Capture current multiplayer requirement and future expectation; authority,
serialization, persistence, determinism, client/server, and replay implications
without choosing a network model by default. Pin exact versions in native
manifests/lockfiles/tool files. Verify uncertain/version-sensitive APIs against
current official sources and record durable reference notes—never model cutoff
assumptions.

Update technical preferences and layout roots. Stack/product migrations are
material decisions; ordinary setup/install/edit/commit/push inside an agreed
choice proceeds directly. Deployment, credentials, billing, and external-account
actions require explicit authority.

# Agent Coordination Rules

## Lean Default

The main Codex session owns integration and may consult the most relevant
specialist directly for a bounded task. Organizational tiers describe expertise,
not mandatory routing hops. Leadership roles are filters, reviewers, and
decision facilitators when their perspective adds value.

## Active Role Set

Each project or milestone may define:

- **Continuously active** roles for recurring implementation and review.
- **Consulted** roles invoked for a subsystem, risk, or bounded question.
- **Milestone reviewers** who assess integrated outcomes at meaningful gates.

Keep the set as small as the current stage permits. A role matrix may live in
project production or architecture documentation; the reusable framework does
not choose it for the game.

## Review Selection

- Routine, local changes need the implementer and proportionate verification.
- Consult a domain specialist when the change needs expertise not already in
  the active session.
- Add leadership or cross-domain review for high-impact architecture, product
  direction, security, data-loss, economy, accessibility, release, or changes
  spanning several systems.
- Resolve disagreements with the smallest relevant decision group. Escalate to
  the user for product direction, scope, irreversible actions, or unresolved
  tradeoffs.
- Avoid parallel edits to the same files; the main session consolidates results.

Agents may edit any in-scope files needed for an agreed task. Domain labels are
guidance for expertise and review, not file ownership barriers.

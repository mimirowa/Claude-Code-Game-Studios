# Review Workflow

Apply review in proportion to risk and project configuration:

1. Routine local changes: author verification and normal code review if the
   project uses it.
2. Subsystem changes: consult the relevant specialist when useful.
3. Cross-domain or high-impact changes: review with affected domain roles and an
   appropriate lead or director.
4. Milestones and releases: use the project's designated milestone reviewers.
5. Product direction, scope changes, destructive actions, releases/deployment,
   credentials, billing, and external-service commitments return to the user.

Do not require ceremonial approval from every role. Document review evidence,
open risks, and decisions that materially affect future work.
